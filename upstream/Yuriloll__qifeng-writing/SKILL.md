# 起风个人 IP 中文写作

把中文创作技法转化为可执行的写作决策：先判断问题出在哪一层，再选择适合当前文体、位置和目标的技法。不要为了展示技法而过度修改。

## 适用范围

主要处理：

- X 单条推文、Thread、QT、长推和 X Article
- 公众号文章、观点评论、知识解释、个人经历、叙事非虚构
- 项目介绍、产品说明和自然推广文案
- 已有草稿的诊断、局部优化、全文重构、压缩和扩写

以下请求应让更专门的能力优先处理：

- 只研究或批量生成高互动开头：`tweet-hook`
- 只要求去 AI 味：`rn-renhua`
- 只处理公众号标题：`gzh-title-strategist`
- 公众号定位、运营、排版或发布：`wechat-aip-architect`
- 纯小说、诗歌、剧本创作

本 Skill 必须能够独立完成普通开头、标题、自然化和文章优化；上述 Skill 是可选专门路径，不是依赖项。

## 工作模式

### 1. 从零创作

用户给出主题、素材、观点或来源后，先确定文体、目标读者、核心问题、事实边界和结构动力，再写成稿。内部完成诊断即可；除非用户要求，不要先交一份长分析。

### 2. 只诊断

用户说“先分析”“先判断”“先不要改”“先别给新版本”时：

- 只指出问题、位置、影响和候选技法。
- 不输出任何改写稿、示范段或“顺手优化版”。
- 可以说明建议的修改顺序。

### 3. 局部优化

用户指定开头、结尾、标题、某段、某句或某种问题时：

- 只修改明确范围。
- 未指定部分保持原文，不进行连带润色。
- 需要改动相邻内容才能成立时，先说明影响并请求允许；不要自行扩大边界。

### 4. 全文优化

先处理高层问题：立意与事实 → 结构与论证／叙事 → 段落 → 句子 → 修辞。不要用词语润色掩盖中心不清、证据不足或因果断裂。

### 5. 技法解释

只有用户询问“用了什么技法”“为什么这样改”时，输出问题、技法、作用与边界。普通请求以可发布文本为主。

## 决策流程

1. **锁定硬约束**：文体、平台、读者、目标、长度、必须保留的开头／句子／术语／事实／链接、禁止改动范围。
2. **识别内容类型**：观点、经历、新闻评论、知识解释、教程、推广、叙事或混合型。
3. **判断最高层问题**：内容与证据、结构、叙事／论证、段落、句式、风格。
4. **选择最小充分技法集**：通常先选一项主技法，再补必要的支撑技法；没有问题就不加技法。
5. **检查前提与冲突**：例如场景需要真实材料，悬念不适合必须立即公布结论的说明，含蓄不能损害事实准确。
6. **按授权范围执行**：局部只改局部，全文才允许重构。
7. **质量复核**：核对事实、原意、逻辑、语气、平台可读性和个人风格。

## 硬性原则

- 用户给出的事实、数字、人名、产品名、术语、日期、链接、经历和不确定性默认不得改变。
- 不新增未经支持的案例、数据、效果、对话、内心活动、个人经历或来源。
- 时效性事实影响成稿时，按当前环境规则核验；不能核验就明确保留不确定性。
- 用户指定准确开头或结尾时，将其视为硬约束，除非用户允许改动。
- 不把用户的具体经历改写成泛化的励志故事。
- 不把推广文案扩写成产品说明书；只保留任务所需卖点。
- 不把所有文章写成“钩子＋三个要点＋总结”。结构必须服从内容。
- 不滥用反问、排比、金句、悬念、反转和宏大升华。
- 起风个人 IP 的公开写作禁止使用“先否定、后揭示或肯定”的修辞骨架；同构换词、拆句和跨句变体同样禁用。除不可改动的直接引语外，命中后必须重写，完整规则见 [AI 味句式黑名单](references/ai-style-blacklist.md)。
- 创作、重写和润色在交付前必须执行 AI 味黑名单复核；A 组零命中，B 组按语境、证据和密度处理。
- 普通正文使用自然连续段落，避免一行一句和碎片化排版。
- 技法名不能替代分析。必须说明当前文本的具体问题与技法为何匹配。

## 技法选择规则

采用：

`问题信号 → 候选技法 → 使用前提 → 预期效果 → 风险 → 最终选择`

优先级：

1. 事实与核心问题
2. 结构动力和材料取舍
3. 叙事或论证完整性
4. 段落与信息流
5. 句式、节奏与词语
6. 修辞与艺术性

同一技法可能跨层存在，例如层递、回环、反问和重复。以当前作用为准，不重复计算，也不为了“多用技法”叠加同义操作。

## 默认输出

### 普通创作或优化

先给一份最佳成稿，再用极简说明列出主要技法及其解决的问题。

### 用户说“只要文案”

只给成稿，不附诊断、技法名或解释。

### 用户要求局部修改

只交付修改后的局部；如需定位，使用简短标签，不重印全文。

### 用户要求诊断

按“位置—问题—影响—建议技法—边界”输出，不给新版本。

### 备选版本

只有用户要求多个版本，或存在真实且重要的风格取舍时才提供。默认不给大量同义改写。

## 完成标准

交付前确认：

- 是否遵守了用户的编辑边界？
- 是否保留了所有硬约束和事实边界？
- 是否选择了最高价值问题，而非只改表面词语？
- 使用的技法是否有材料前提，是否与文体相容？
- 每一段是否推进信息、认识、行动、关系或情绪？
- 是否仍然像作者本人，而非统一的“漂亮 AI 文风”？
- AI 味句式黑名单 A 组是否零命中，B 组是否已经逐项复核？
- 推文是否可以直接发布，文章是否可以连续阅读？
